# qwdtt-cli

Консольный клиент к протоколу qWDTT: VPN поверх TURN-инфраструктуры звонков VK.
Трафик уходит на ваш VPS через TURN-relay ВКонтакте и для сети выглядит как медиапоток
звонка WebRTC, а не как подключение к VPN-серверу.

Это только клиент. Установка и настройка серверной части, панель управления, импорт
подписок и сканирование QR остаются в Android-приложении
[qWDTT](https://github.com/SpaceNeuroX/proxy-turn-vk-android) — здесь их нет и не будет.
Чтобы подключиться, у вас уже должны быть адрес сервера, пароль подключения и хотя бы
один хеш звонка VK — те же, что вводятся в приложении.

Клиент работает на переднем плане: пока запущен `tt connect`, туннель поднят.
Службы и автозапуска нет. Первый Ctrl+C останавливает туннель и убирает за собой,
второй убивает процесс.

## Установка

Готовая сборка — архив `tt_<версия>_windows_amd64.zip`: распакуйте в любой каталог,
в нём `tt.exe`, пример настроек `tt.example.toml`, лицензия и этот файл. Установка
не нужна, права администратора для режима по умолчанию — тоже.

Сборка из исходников (нужен Go 1.26 или новее, cgo не требуется):

```
go build -o tt.exe ./cmd/tt
```

Релиз для трёх платформ собирает `pwsh scripts/build-release.ps1`. Бинари для Linux
и macOS собираются и запускаются, но в этом выпуске не проверялись вживую: режим
`external` там не поддерживается.

## Быстрый старт

1. Заведите профиль. Пароль и хеши спрашиваются скрытым вводом; в файл настроек
   попадают только ссылки на хранилище секретов (на Windows — DPAPI, привязка к вашей
   учётной записи):

   ```
   tt profile set home -peer example.org:56000
   ```

2. Проверьте хеши и задержку до сервера. Обе команды не поднимают туннель:

   ```
   tt hashes
   tt ping
   ```

   `hashes` печатает по строке на хеш со статусом `ok`, `captcha`, `dead`, `limited`,
   `network` или `error` и возвращает код 1, если годных нет.

3. Поднимите туннель:

   ```
   tt connect
   ```

   Через секунду-две в выводе появится `[SOCKS] слушает 127.0.0.1:1080` и
   `== туннель работает`. Направьте на этот адрес браузер или приложение, которое
   умеет ходить через прокси SOCKS5. Проверить можно так:

   ```
   curl -x socks5h://127.0.0.1:1080 https://example.org/
   ```

   Имя профиля можно опускать, если профиль один или назван в `default_profile`.
   Флаг перекрывает то же поле профиля на один запуск: `tt connect home -workers 27`.
   `-v` печатает весь лог ядра. На терминале внизу держится статусная строка
   с состоянием, аптаймом и счётчиками; при перенаправлении в файл её нет.

Если VK попросит капчу, которую ядро не осилило само, на Windows откроется окно
со страницей капчи: решите её, и окно закроется само, а `tt` продолжит. Срок
написан в заголовке окна. Если окна не видно, оно может оказаться за консолью —
поищите его на панели задач. Окну нужен WebView2 Runtime: он есть в Windows 11 и в актуальных
Windows 10. Если Runtime нет, если `tt` запущен по SSH или система не Windows,
в stderr вместо окна появится ссылка и инструкция: открыть её в браузере, решить,
вставить токен. На это даётся три минуты.

## Файл настроек

`profiles.toml` лежит в каталоге настроек пользователя: на Windows это
`%APPDATA%\qwdtt-cli\`, рядом — `secrets.json` с зашифрованными секретами.
Другой путь — флаг `-config`. Файл правится командой `tt profile set` или руками,
пример со всеми полями и пояснениями — [`tt.example.toml`](tt.example.toml).

| Поле | Что задаёт | По умолчанию |
|---|---|---|
| `peer` | адрес сервера `host:port` | обязательно |
| `password_ref`, `vk_hashes_ref` | ссылки на секреты, пишет `tt profile set` | обязательно |
| `workers` | число воркеров, кратно девяти, потолок 108 | 9 |
| `obfs` | RTP-маскировка: `audio` или `video` | `audio` |
| `turn_transport` | `udp` или `tcp`; TCP помогает там, где душат UDP | `udp` |
| `dtls` | DTLS поверх TURN; `false` требует сервера с `-listen-direct` | `true` |
| `dns` | резолвер для доменов VK: `yandex`, `cloudflare`, `google`, `doh-*`, `custom:IP`, `doh:URL` | `yandex` |
| `datapath` | как отдавать трафик: `socks` или `external` | `socks` |
| `[profile.<имя>.socks] listen` | адрес локального SOCKS5 | `127.0.0.1:1080` |

Секреты просматриваются только замаскированными (`tt profile show`), удаляются
вместе с профилем (`tt profile rm`) и перезаписываются по `tt profile set <имя>
-password` или `-hashes`. Аргументом командной строки их передать нельзя намеренно.

## Режимы доставки трафика

**`socks`** (по умолчанию) — WireGuard целиком внутри процесса и локальный SOCKS5
над ним. Прав администратора не нужно, устанавливать ничего не нужно. Ограничения:
только TCP, только IPv4, только приложения, которые умеют ходить через прокси;
DNS-запросы приложения уйдут мимо туннеля, если оно не проксирует их само
(в `curl` для этого `socks5h`, в браузерах — настройка «DNS через прокси»).

**`external`** — конфиг от сервера передаётся штатному WireGuard для Windows:
`wireguard.exe /installtunnelservice` ставит службу туннеля, при остановке она
снимается. Нужны установленный [WireGuard](https://www.wireguard.com/install/) и
консоль от имени администратора. Пока туннель поднят, служба видна в
`services.msc` как «WireGuard Tunnel: tt», а её конфиг с приватным ключом лежит в
`%APPDATA%\qwdtt-cli\tt.conf`: служба читает его при запуске. При остановке `tt`
снимает службу и удаляет файл.

> **В этом выпуске `external` работает только со сплит-конфигом.** Штатный WireGuard
> забирает весь трафик системы, включая собственные соединения `tt` с VK и TURN, и
> подключение зацикливается. Сервер qWDTT сейчас выдаёт `AllowedIPs = 0.0.0.0/0`,
> поэтому туннель в этом режиме поднимется, только если серверная сторона отдаёт
> список подсетей, не покрывающий адреса VK. Обход через привязку сокетов ядра
> к физическому адаптеру — следующий этап. Клиент предупреждает об этом при запуске.
>
> Если `tt` был убит, а не остановлен, служба и файл конфига могли остаться: снимите
> службу командой `wireguard.exe /uninstalltunnelservice tt` и удалите
> `%APPDATA%\qwdtt-cli\tt.conf`.

## Восстановление

При обрыве клиент переподключается сам с нарастающей задержкой; смена сети
переживается так же. Хеш, по которому VK отвечает «звонок закрыт», исключается
из перебора; когда годных не остаётся, клиент останавливается с ошибкой —
заведите новые через `tt profile set <имя> -hashes`.

## Предупреждения

Релизные бинари не подписаны. Windows SmartScreen и антивирусы могут возражать
против программы, которая держит сетевой туннель, — это ожидаемо до появления
подписи. Исходники открыты, сборка воспроизводима скриптом из репозитория.
