# Воспроизведение ошибок ядра для апстрима

Набор к [`upstream-proposals.md`](../upstream-proposals.md): тесты и патчи для
`go_client` апстрима (SpaceNeuroX/proxy-turn-vk-android, коммит `fae121e`). В issue можно
дать ссылку на этот каталог или приложить файлы.

## Что внутри

| Файл | Что это |
|---|---|
| `repro_test.go` | тесты для `go_client/` (пакет `main`): по тесту на пункты 1, 2, 3, 5а, 5б |
| `1-closed-call.patch` | правка пункта 1 — закрытый звонок (954) → `dead` |
| `2-baton.patch` | правка пункта 2 — эстафета групп при ошибке кредов |
| `3-config-quota.patch` | правка пункта 3 — конфиг просит каждый воркер |
| `5-stop.patch` | правка пункта 5 — остановка во время `GETCONF` и гонка дедлайна чтения |
| `run.sh` | всё сразу: прогон на чистом апстриме, потом с патчами |

Патчи — `git diff` относительно `fae121e`, накладываются в корне репозитория апстрима
(`git apply 2-baton.patch`) по одному или все вместе. Пункт 4 (счётчики) — не ошибка, патча
и теста для него нет.

## Как запустить

```
./run.sh              # клонирует апстрим во временный каталог
./run.sh <клон>       # или готовый клон; его рабочее дерево сбрасывается
```

Нужны git и Go 1.26 (скрипт просит `go1.26.2`: в `go.mod` апстрима — «go 1.26», под таким
именем Go не скачивается). У апстрима `go.sum` в `.gitignore`, поэтому скрипт делает
`go mod tidy`. Прогон — около двух с половиной минут.

Вручную, без скрипта: положить `repro_test.go` в `go_client/`, `go mod tidy`,
`go test -tags upstream_repro -run TestRepro -v .`. Тег сборки нужен потому, что файл лежит в
нашем репозитории и здесь собираться не должен.

## Что должно получиться

На `fae121e` без правок:

```
--- FAIL: TestReproClosedCallIsDead              статус "error", ожидался dead
--- FAIL: TestReproGroupPassesBatonOnCredsFailure эстафета не передана
--- FAIL: TestReproConfigDespiteQuota            486 отдано 4 раз, GETCONF 0, сеансов 3
--- FAIL: TestReproStopDuringConfigRequest       вернулась через 45 с
--- SKIP: TestReproStopRightAfterSessionStart    без вставленной задержки
гонка 5б с задержкой: FAIL — не вернулась и через 65 с
```

С патчами 1, 2, 3, 5 — всё `PASS` (конфиг через 1,6 с, остановка 5а — 0,1 с, 5б — 0,4 с).

## Про тест 5б

Гонка, которую он ловит, длится микросекунды: остановка должна прийти между началом
чтения сеанса и его `SetReadDeadline`. Без помощи тест почти всегда проходит и на старом
коде, поэтому без `REPRO_INJECT_DELAY=1` он пропускается. `run.sh` вставляет
`time.Sleep(300 * time.Millisecond)` перед этим `SetReadDeadline` (только на время прогона)
и останавливает группу через 100 мс после получения конфига — посреди этого сна. Это
демонстрация, а не постоянный тест.

## Как сделано

Стенд в `repro_test.go` — тот же, что у нас в `internal/core/quota_stand_test.go`, без наших
событий (апстрим пишет лог через `log.Printf`). Патчи собраны теми же регулярными
выражениями, что правила `scripts/vendorcore/rules.go`, с комментариями для апстрима.
Проверено: `run.sh` на чистом клоне апстрима даёт ровно результат выше.
